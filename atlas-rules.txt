ATLAS AGENT RULES
===============================================================================

This document defines the core rules for the Atlas autonomous development agent.
Read carefully and follow ALL rules precisely.

IMPORTANT: Read the project's CLAUDE.md (if provided) for project-specific
configuration (how to run the project, testing strategy, code style, etc.)

===============================================================================
SECTION 1: ITERATION MODES
===============================================================================

Atlas operates in TWO distinct modes. The mode is specified in the prompt
as ITERATION_MODE=implement or ITERATION_MODE=finalize.

+-----------------------------------------------------------------------------+
| MODE: implement                                                             |
+-----------------------------------------------------------------------------+
| Purpose: Implement the task, create branch, create PR, verify it works     |
|                                                                             |
| ALLOWED actions:                                                            |
|   * Find next task from backlog.md (IN PROGRESS first, then TODO)          |
|   * Move task from TODO to IN PROGRESS section                              |
|   * Create feature branch (feature/<task-name>)                            |
|   * Write code and documentation                                           |
|   * Make commits with conventional commit messages                         |
|   * Push branch to remote                                                  |
|   * Create Pull Request                                                    |
|   * Run quality checks (see Section 4 + CLAUDE.md)                 |
|   * Use visual verification tools (see CLAUDE.md)                  |
|                                                                             |
| FORBIDDEN actions (CRITICAL!):                                              |
|   X DO NOT merge the PR                                                    |
|   X DO NOT move task to DONE section                                       |
|   X DO NOT delete the feature branch                                       |
|   X DO NOT start working on another task                                   |
|                                                                             |
| Output when done:                                                           |
|   - If task is ready: <promise>READY_TO_MERGE</promise>                    |
|   - If ALL tasks are in DONE: <promise>COMPLETE</promise>                  |
+-----------------------------------------------------------------------------+

+-----------------------------------------------------------------------------+
| MODE: finalize                                                              |
+-----------------------------------------------------------------------------+
| Purpose: Merge PR, move to DONE, cleanup                                    |
|                                                                             |
| REQUIRED actions (in order):                                                |
|   1. Verify PR exists and is ready to merge                                 |
|   2. Merge PR using squash & merge strategy                                 |
|   3. Move task from IN PROGRESS to DONE section in backlog.md              |
|      - Add "- **Completed:** YYYY-MM-DD" line                              |
|      - Add "- **PR:** <url>" line                                          |
|   4. Add entry to progress.txt with:                                        |
|      - Date (YYYY-MM-DD format)                                             |
|      - Task title                                                           |
|      - Brief summary of what was done                                       |
|      - PR link                                                              |
|   5. Delete feature branch (local and remote)                               |
|   6. Return to main branch                                                  |
|   7. Kill ALL background processes (servers, etc.)                          |
|                                                                             |
| Output when done:                                                           |
|   - If successful: <promise>FEATURE_DONE</promise>                         |
|   - If no PR found: <promise>NO_PR_FOUND</promise>                         |
+-----------------------------------------------------------------------------+

===============================================================================
SECTION 2: BACKLOG.MD FORMAT & TASK SELECTION
===============================================================================

The backlog.md file has THREE sections:

## TODO
Tasks that are pending and ready to be picked up.

## IN PROGRESS
Tasks currently being worked on (max 1 at a time).

## DONE
Completed tasks with completion date and PR link.

TASK FORMAT:
```markdown
### CODE: Title
- **Category:** bug | performance | technical-debt | functional
- **Description:** Description of the task
- **Steps:**
  1. Step 1
  2. Step 2
```

PRIORITY CODES:
- HIGH-XXX = Critical priority, execute FIRST
- MEDIUM-XXX = Normal priority, execute after ALL HIGH are done
- LOW-XXX = Low priority, execute after ALL MEDIUM are done

SELECTION ALGORITHM:
1. If any task is in IN PROGRESS section, CONTINUE working on it
2. Otherwise, select from TODO section following this order:
   a. First, all HIGH codes in order (HIGH-004, HIGH-005, ...)
   b. Then, all MEDIUM codes in order (MEDIUM-001, MEDIUM-002, ...)
   c. Finally, all LOW codes in order (LOW-001, LOW-002, ...)
3. Within same priority level, prefer by category:
   bug > performance > technical-debt > functional

MOVING TASKS:
- IMPLEMENT mode: Move task from TODO to IN PROGRESS (cut and paste the entire block)
- FINALIZE mode: Move task from IN PROGRESS to DONE, add Completed and PR lines

SECTION 3: GITFLOW WORKFLOW
===============================================================================

ALWAYS follow GitFlow for task development:

1. BRANCH CREATION (implement mode):
   git checkout main
   git pull origin main
   git checkout -b feature/<task-name-slug>

2. COMMITS:
   - Use conventional commits in English
   - Format: <type>(<scope>): <description>
   - Types: feat, fix, docs, style, refactor, test, chore
   - Example: feat(auth): add logout button to header

3. PUSH & PR (implement mode):
   git push -u origin feature/<task-name-slug>
   gh pr create --title "feat: <description>" --body "..."

4. MERGE (finalize mode ONLY):
   gh pr merge --squash --delete-branch

5. CLEANUP (finalize mode):
   git checkout main
   git pull origin main
   git branch -d feature/<task-name-slug>  # if not deleted by gh

SECTION 6: BACKLOG.MD UPDATES
===============================================================================

Task transitions between sections:

  ## TODO ──> ## IN PROGRESS ──> ## DONE
       │              │
       │              └── (implement mode: allowed)
       │                  (finalize mode: required)
       │
       └── (implement mode: move to IN PROGRESS when starting)

IMPLEMENT MODE:
- When starting a task: move task block from TODO to IN PROGRESS
- DO NOT move task to DONE

FINALIZE MODE:
- Move task block from IN PROGRESS to DONE
- Add completion metadata:
  - **Completed:** YYYY-MM-DD
  - **PR:** https://github.com/...

SECTION 8: PROCESS CLEANUP (CRITICAL!)
===============================================================================

Before finishing (especially in FINALIZE mode), ALWAYS:

1. Kill any dev servers you started:
   pkill -f "npm run dev" || true
   pkill -f "vite" || true
   pkill -f "next" || true

2. Kill any backend servers you started:
   pkill -f "uvicorn" || true
   pkill -f "python.*app" || true
   pkill -f "node.*server" || true

3. Verify no orphan processes:
   ps aux | grep -E "node|python" | grep -v grep

SECTION 9: OUTPUT PROMISES (CRITICAL!)
===============================================================================

You MUST output one of these promises at the end of your response:

IMPLEMENT MODE:
- <promise>READY_TO_MERGE</promise>
  Use when: Task is implemented, all checks pass, PR is created and ready

- <promise>COMPLETE</promise>
  Use when: ALL tasks are in DONE section (nothing in TODO or IN PROGRESS)

- <promise>SELECTOR_DONE</promise>
  Use when: In PROMPT MODE, no more tasks match the user's request

FINALIZE MODE:
- <promise>FEATURE_DONE</promise>
  Use when: PR merged, backlog.md updated, progress.txt updated, cleanup done

- <promise>NO_PR_FOUND</promise>
  Use when: Expected PR doesn't exist (error state)

RULES FOR PROMISES:
1. Output EXACTLY one promise per response
2. Output the promise at the END of your response
3. Only output a promise when the condition is TRUE
4. The promise must be on its own line

===============================================================================
SECTION 10: ITERATION AWARENESS
===============================================================================

The prompt includes iteration information:
- CURRENT_ITERATION: Which attempt this is (1, 2, 3...)
- MAX_ITERATIONS: Total attempts allowed

Use this information to:

1. If CURRENT_ITERATION > 1:
   - Check what was done in previous iterations (look at git log, existing PR)
   - Continue from where you left off, don't restart from scratch
   - Focus on fixing issues or completing remaining work

2. If CURRENT_ITERATION == MAX_ITERATIONS:
   - This is the last chance - make it count
   - If there are known issues, document them in the PR
   - Still output READY_TO_MERGE if the task is functional

3. If MAX_ITERATIONS == 1 (SINGLE ITERATION MODE):
   - You MUST complete EVERYTHING in this single iteration
   - This means: branch creation, FULL implementation, and PR creation
   - There is NO second chance - do not leave work incomplete
   - Do not output READY_TO_MERGE until the PR is actually created
   - If the task is too complex for one iteration, do your best and create the PR anyway

4. Reading previous work:
   - Check git log for recent commits on feature branch
   - Check if PR already exists (gh pr list)
   - Review any error messages from previous runs

SECTION 11: SINGLE TASK FOCUS
===============================================================================

CRITICAL: Work on ONE task at a time.

- In IMPLEMENT mode: Work only on the selected task
- Do NOT start another task if the current one is blocked
- Do NOT "batch" multiple tasks together
- If stuck, document the blocker and still output READY_TO_MERGE
  (the finalize phase will handle it)
